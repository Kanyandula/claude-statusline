# claude-statusline Phase 3 — User-Facing CLI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Stop making users hand-edit `~/.claude/settings.json` and `~/.claude/claude-statusline.json`. After this phase, a single CLI (`claude-statusline`) does install, configuration, preview, and uninstall.

**Architecture:** Add `bin/claude-statusline.js` as the user-facing dispatcher. It routes subcommands (`init`, `render`, `layout`, `enable`, `disable`, `set`, `get`, `preview`, `reset`, `uninstall`) to single-purpose modules under `src/cli/`. The existing `bin/statusline.js` shrinks to a 3-line backward-compat shim that calls the same render logic. `package.json` registers the dispatcher as the package's bin.

**Tech Stack:** Same as Phase 2 — Node ≥18, built-ins only (`node:util`'s `parseArgs` for flag parsing), `node --test`. No new runtime deps.

---

## Context

Phase 2 made layout/fields/thresholds configurable but only via hand-edited JSON. That's fine for the maintainer but a UX cliff for anyone else who installs the tool. Phase 3 closes that cliff: one command sets it up, another switches layout, a third previews changes without touching Claude Code. After this phase, the install story is:

```
npm i -g claude-statusline
claude-statusline init
# done — restart Claude, statusline appears
```

…and the customise story is:

```
claude-statusline layout single
claude-statusline enable apiRatio
claude-statusline preview
```

No JSON editing, no path knowledge, no global-config archaeology.

**Responsibilities (every new file ≤ 80 LOC):**

- `bin/claude-statusline.js` — `#!/usr/bin/env node` shebang, `import { runCli } from '../src/cli/index.js'; runCli(process.argv.slice(2));` — that's it.
- `src/cli/index.js` — parses `argv[0]` as subcommand, dispatches to the matching module, handles `--help`, returns exit code.
- `src/cli/paths.js` — resolves user / project / settings.json paths; uses `homedir()` + `process.cwd()`.
- `src/cli/settings.js` — atomic read-modify-write of `~/.claude/settings.json`; helpers: `getStatusLine()`, `setStatusLine(value)`, `removeStatusLine()`. Always writes to `<file>.tmp` then renames; always backs up to `<file>.bak.<timestamp>` before first write.
- `src/cli/config-file.js` — read-modify-write of `claude-statusline.json` at a given path; helper `setKeyPath(obj, 'fields.cost', false)` for dotted-path assignment.
- Subcommand modules — each exports `run(args) → number` (exit code), one responsibility, all I/O via `paths`/`settings`/`config-file`.
- `src/cli/render.js` — exact logic from current `bin/statusline.js`. Backward-compat shim still works.

## CLI surface (final)

```
claude-statusline <command> [options]

Commands:
  init        Wire claude-statusline into Claude Code (writes statusLine + default config)
  layout      Switch layout: single | two-line
  enable      Turn on a field: project|branch|model|ctx|duration|cost|loc|apiRatio|outputStyle
  disable     Turn off a field
  set         Set any config key by dotted path:  set thresholds.costWarnUsd 3
  get         Print effective config (merged across all layers) as JSON
  preview     Render the statusline once with sample data — handy for testing config
  reset       Restore defaults by deleting the config file (does NOT touch settings.json)
  uninstall   Remove statusLine from settings.json (and config file by default)
  render      Invoked by Claude Code each prompt — reads stdin → writes ANSI
  --help, -h  Print this help

Global options:
  --scope=user|project   Which file to read/write (default: user = ~/.claude/...)
                         project = <cwd>/.claude/...
  --force                Overwrite an existing statusLine entry on init
  --keep-config          Keep claude-statusline.json when uninstalling
```

## settings.json patching contract

`init` writes:

```json
"statusLine": {
  "type": "command",
  "command": "claude-statusline render"
}
```

`uninstall` removes that key. Both operations:
1. Read the file (require valid JSON; fail loudly with location if invalid)
2. Back up to `<file>.bak.<unix-ts>` if not already backed up this minute
3. Apply the change in memory
4. Write to `<file>.tmp` with `JSON.stringify(obj, null, 2)`
5. `rename(<file>.tmp, <file>)` — atomic on POSIX

## KNOWN_FIELDS / LAYOUTS constants

Exported from `src/config.js` so `enable`/`disable`/`set`/`layout` validate against a single source of truth. Re-using `Object.keys(DEFAULT_CONFIG.fields)` for `KNOWN_FIELDS` and a hardcoded `['single', 'two-line']` for `LAYOUTS`.

```js
import { readFileSync, writeFileSync, renameSync, existsSync } from 'node:fs';
import { dirname } from 'node:path';
import { mkdirSync } from 'node:fs';

const SL_KEY = 'statusLine';

function readJson(path) {
  if (!existsSync(path)) return null;
  return JSON.parse(readFileSync(path, 'utf8'));
}

function backupOnce(path) {
  if (!existsSync(path)) return;
  const ts = Math.floor(Date.now() / 1000);
  const bak = `${path}.bak.${ts}`;
  if (!existsSync(bak)) writeFileSync(bak, readFileSync(path));
}

function atomicWrite(path, obj) {
  mkdirSync(dirname(path), { recursive: true });
  const tmp = `${path}.tmp`;
  writeFileSync(tmp, JSON.stringify(obj, null, 2) + '\n');
  renameSync(tmp, path);
}

export function getStatusLine(settingsPath) {
  const s = readJson(settingsPath);
  return s ? s[SL_KEY] ?? null : null;
}

export function setStatusLine(settingsPath, value) {
  const s = readJson(settingsPath) ?? {};
  backupOnce(settingsPath);
  s[SL_KEY] = value;
  atomicWrite(settingsPath, s);
}

export function removeStatusLine(settingsPath) {
  const s = readJson(settingsPath);
  if (!s || !(SL_KEY in s)) return false;
  backupOnce(settingsPath);
  delete s[SL_KEY];
  atomicWrite(settingsPath, s);
  return true;
}
```

```js
import { readFileSync, writeFileSync, existsSync, renameSync, unlinkSync, mkdirSync } from 'node:fs';
import { dirname } from 'node:path';

export function readConfigFile(path) {
  if (!existsSync(path)) return {};
  try {
    const raw = readFileSync(path, 'utf8');
    const parsed = JSON.parse(raw);
    return parsed && typeof parsed === 'object' && !Array.isArray(parsed) ? parsed : {};
  } catch {
    return {};
  }
}

export function writeConfigFile(path, obj) {
  mkdirSync(dirname(path), { recursive: true });
  const tmp = `${path}.tmp`;
  writeFileSync(tmp, JSON.stringify(obj, null, 2) + '\n');
  renameSync(tmp, path);
}

export function deleteConfigFile(path) {
  if (existsSync(path)) unlinkSync(path);
}

// Set a nested key by dotted path: setKeyPath(obj, 'fields.cost', false).
// Coerces simple value types when given a string: 'true'/'false' → boolean,
// numeric strings → number, otherwise raw string.
export function coerceValue(raw) {
  if (typeof raw !== 'string') return raw;
  if (raw === 'true') return true;
  if (raw === 'false') return false;
  if (raw === 'null') return null;
  if (raw !== '' && !Number.isNaN(Number(raw))) return Number(raw);
  return raw;
}

export function setKeyPath(obj, dotted, value) {
  const parts = dotted.split('.');
  let cur = obj;
  for (let i = 0; i < parts.length - 1; i++) {
    const k = parts[i];
    if (typeof cur[k] !== 'object' || cur[k] === null || Array.isArray(cur[k])) cur[k] = {};
    cur = cur[k];
  }
  cur[parts[parts.length - 1]] = value;
  return obj;
}
```

Move the existing logic from `bin/statusline.js` into a `runRender()` function:

```js
import { homedir } from 'node:os';
import { join } from 'node:path';
import { renderFromStdin } from '../pipeline.js';
import { loadConfig } from '../config.js';
import { getGitInfo } from '../git.js';

const MAX_STDIN_BYTES = 1_000_000;

function computeColour() {
  if (process.env.NO_COLOR) return false;
  if (process.env.FORCE_COLOR) return true;
  if (process.stdin && process.stdin.isTTY !== true) return true;
  return process.stdout && process.stdout.isTTY === true;
}

export function runRender() {
  process.stdout.on('error', (err) => {
    if (err.code === 'EPIPE') process.exit(0);
  });

  const userPath = process.env.CLAUDE_STATUSLINE_CONFIG
    || join(homedir(), '.claude', 'claude-statusline.json');

  let raw = '';
  process.stdin.setEncoding('utf8');
  process.stdin.on('data', d => {
    if (raw.length >= MAX_STDIN_BYTES) return;
    raw += d;
    if (raw.length > MAX_STDIN_BYTES) raw = raw.slice(0, MAX_STDIN_BYTES);
  });
  process.stdin.on('end', () => {
    try {
      let projectPath = null;
      try {
        const parsed = JSON.parse(raw || '{}');
        const cwd = parsed?.workspace?.current_dir || parsed?.cwd;
        if (cwd) projectPath = join(cwd, '.claude', 'claude-statusline.json');
      } catch { /* projectPath stays null; pipeline parses independently */ }

      const config = loadConfig({ userPath, projectPath, env: process.env });
      const colour = computeColour();
      process.stdout.write(renderFromStdin(raw, { config, gitFn: getGitInfo, colour }));
    } catch (e) {
      if (process.env.CLAUDE_STATUSLINE_DEBUG) process.stderr.write(`statusline error: ${e}\n`);
    }
  });
}
```

```js
  layout      Switch layout: single | two-line
  enable      Turn on a field
  disable     Turn off a field
  set         Set a config key by dotted path
  get         Print effective config as JSON
  preview     Render the statusline once with sample data
  reset       Restore defaults (deletes config file)
  uninstall   Remove statusLine from settings.json
  render      Internal — invoked by Claude Code each prompt
  --help, -h  Print this help
`;

export function runCli(argv) {
  if (argv.length === 0 || argv[0] === '--help' || argv[0] === '-h') {
    process.stdout.write(HELP);
    return 0;
  }
  const cmd = argv[0];
  const rest = argv.slice(1);
  switch (cmd) {
    case 'render': {
      // dynamic import keeps render's heavy stdin-handling out of the synchronous dispatch path
      import('./render.js').then(({ runRender }) => runRender());
      return 0;
    }
    case 'init':
    case 'layout':
    case 'enable':
    case 'disable':
    case 'set':
    case 'get':
    case 'preview':
    case 'reset':
    case 'uninstall':
      process.stderr.write(`claude-statusline: '${cmd}' not implemented yet\n`);
      return 1;
    default:
      process.stderr.write(`claude-statusline: unknown command '${cmd}'\n${HELP}`);
      return 64;
  }
}
```

```js
import { parseArgs } from 'node:util';
import { existsSync } from 'node:fs';
import { resolveSettingsPath, configPathForScope } from './paths.js';
import { getStatusLine, setStatusLine } from './settings.js';
import { writeConfigFile } from './config-file.js';

const SL_BLOCK = { type: 'command', command: 'claude-statusline render' };

export function run(argv) {
  const { values } = parseArgs({
    args: argv,
    options: {
      scope: { type: 'string', default: 'user' },
      force: { type: 'boolean', default: false },
    },
    allowPositionals: false,
  });
  if (!['user', 'project'].includes(values.scope)) {
    process.stderr.write(`init: --scope must be 'user' or 'project'\n`);
    return 2;
  }

  const settingsPath = resolveSettingsPath();
  const existing = getStatusLine(settingsPath);
  if (existing && !values.force) {
    process.stderr.write(`init: statusLine already configured in ${settingsPath}. Pass --force to overwrite.\n`);
    return 1;
  }
  setStatusLine(settingsPath, SL_BLOCK);

  const configPath = configPathForScope(values.scope);
  if (!existsSync(configPath)) {
    writeConfigFile(configPath, {});
  }

  process.stdout.write(
    `Wired claude-statusline into ${settingsPath}.\n` +
    `Config file: ${configPath} (defaults apply).\n` +
    `Restart Claude Code for the change to take effect.\n`
  );
  return 0;
}
```

- **Spec coverage**: every subcommand from the Phase 3 outline is a task. The render shim (Task 2) is the bridge that keeps old wiring working while the new CLI ships.
- **Placeholder scan**: Tasks 6, 7, 8 are slightly less code-detailed than 1–5 (e.g. "implement `set-get.js` (full code in plan body — split runSet / runGet exports)" leaves the literal source for the implementer). This is deliberate: those subcommands are highly mechanical given the foundation (Task 1) and the dispatcher pattern established by Task 4. If implementer flags ambiguity, controller fills in.
- **Type consistency**: every subcommand returns a numeric exit code; the dispatcher type is `(argv: string[]) → Promise<number>`. `setKeyPath` is the shared mutation primitive. `configPathForScope` is the single path resolver.
- **Risks flagged**:

  - Atomic write via `tmp + rename` is POSIX-safe; on Windows, `rename` may fail if the target exists. Acceptable risk — Phase 3 doesn't claim Windows support.
  - `npm link` smoke test assumes the user is allowed to write to global node_modules. For locked-down systems we'll add a `~/.local/bin` install path option in Phase 5.
