# claude-statusline Phase 5 — Distribution Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make `claude-statusline` installable by anyone — `npm i -g claude-statusline` (primary), `curl ... | sh` (locked-down environments) — backed by a public GitHub repo with CI, issue templates, and a tagged release.

**Architecture:** No new source modules. Phase 5 is infrastructure: GitHub repo, GitHub Actions, issue templates, `install.sh`, `.npmignore`/`files` cleanup, npm publish, GitHub Release. Plus three small carry-over code fixes from Phase 4 review.

**Tech Stack:** Same — Node ≥18, built-ins only, `node --test`, zero deps. New tooling: `gh` CLI for GitHub operations, `npm publish` for the registry.

---

## Context

After Phase 4 the tool is feature-complete, documented, and tested (268 tests). What it isn't: published. A real installation flow for a stranger looks like:

```
npm i -g claude-statusline
claude-statusline init
```

But the package isn't on the npm registry, isn't on GitHub, has no CI, no install fallback for restricted environments, no issue templates. Phase 5 ships all of that.

## Decisions required at execution time

Three choices the user must make when this plan runs:

1. **Stable version label** — `v0.5.0-dist` (matches the phase pattern) or `v1.0.0` (signals stability). Recommend `v1.0.0` since the surface is intentionally complete and we want to signal that to consumers; bump the package.json version accordingly.
2. **npm package name** — `claude-statusline` is the preferred name. If `npm view claude-statusline` shows it's taken, fall back to `@<username>/claude-statusline` (scoped). Decision happens in T6.
3. **Author info for LICENSE + package.json** — copyright line + npm `author` field. The current LICENSE has `claude-statusline contributors` as a placeholder; T1 replaces it with the user's chosen name + year.

These three decisions become AskUserQuestion prompts during execution.

### Task 7: Curl install script — `install.sh`

**Files:**
- Create: `install.sh` (executable, committed at repo root)
- Modify: `README.md` (add curl install as a documented alternative)

For users who can't run `npm i -g` (locked-down work machines, no Node/npm access). The script downloads the renderer JS from GitHub raw, drops it into `~/.claude/helpers/`, and edits `~/.claude/settings.json` to wire it up.

Critically: this install path doesn't ship the CLI (no `claude-statusline` binary), only the renderer. Users who install this way must edit config manually or upgrade to the npm install when possible. Be explicit about that trade-off in the prompt.

- [ ] **Step 1: Write `install.sh`**

```bash
#!/bin/sh
# install.sh — curl install for claude-statusline
# Usage: curl -fsSL https://raw.githubusercontent.com/<user>/claude-statusline/main/install.sh | sh
#
# This installs ONLY the render-side script — not the full CLI. Use this on
# machines where `npm i -g claude-statusline` isn't an option. Run
# `npm i -g claude-statusline` later to upgrade to the full CLI.
set -eu

REPO="<user>/claude-statusline"
HELPER_DIR="$HOME/.claude/helpers"
HELPER_FILE="$HELPER_DIR/claude-statusline.js"
SETTINGS="$HOME/.claude/settings.json"
RAW_BASE="https://raw.githubusercontent.com/$REPO/main"

echo "Installing claude-statusline renderer into $HELPER_DIR…"

mkdir -p "$HELPER_DIR"

# Download the renderer + every src/ file it imports
# (Use a bundled standalone file in Phase 5b if this dependency list grows.)
for f in bin/statusline.js \
         src/cli/render.js \
         src/cli/paths.js \
         src/cli/colour.js \
         src/cli/config-file.js \
         src/cli/fs-util.js \
         src/pipeline.js \
         src/input.js \
         src/adapters/claude.js \
         src/render.js \
         src/format.js \
         src/models.js \
         src/ansi.js \
         src/config.js \
         src/git.js; do
  dest="$HELPER_DIR/$f"
  mkdir -p "$(dirname "$dest")"
  curl -fsSL "$RAW_BASE/$f" -o "$dest"
done

echo "Renderer installed at: $HELPER_FILE"

# Edit settings.json if jq is available
if command -v jq >/dev/null 2>&1; then
  if [ -f "$SETTINGS" ]; then
    cp "$SETTINGS" "$SETTINGS.bak.$(date +%s)"
    jq --arg cmd "node $HELPER_DIR/bin/statusline.js" \
       '. + {statusLine: {type: "command", command: $cmd}}' \
       "$SETTINGS" > "$SETTINGS.tmp" && mv "$SETTINGS.tmp" "$SETTINGS"
  else
    mkdir -p "$(dirname "$SETTINGS")"
    cat > "$SETTINGS" <<EOF
{
  "statusLine": {
    "type": "command",
    "command": "node $HELPER_DIR/bin/statusline.js"
  }
}
EOF
  fi
  echo "Wired into $SETTINGS"
else
  echo
  echo "jq not found — add the following to $SETTINGS manually:"
  echo
  echo '  "statusLine": {'
  echo '    "type": "command",'
  echo "    \"command\": \"node $HELPER_DIR/bin/statusline.js\""
  echo '  }'
  echo
fi

echo "Done. Restart Claude Code to see the statusline."
```

NOTE: the file list (15 files) is brittle — if `src/` modules ever rearrange, this script breaks silently. A Phase 5b cleanup could bundle everything into a single file via `esbuild --bundle --platform=node` before download, eliminating the file list. For Phase 5, the brittle list is acceptable.
